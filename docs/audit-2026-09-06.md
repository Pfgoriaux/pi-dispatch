## Remaining risks and next work

1. **Preserve unfinished work before cleanup.** `removeWorktree` still force-removes
   worktrees and their files. A worker's successful prose report is not proof
   that its edits were committed; keeping only a branch cannot preserve those
   edits. Age-based `pruneStale` also lacks a live-worker lease. Add dirty-tree
   salvage and explicit liveness checks before unattended writes.
2. **Own the complete child lifecycle.** Abort currently signals the direct Pi
   child, not a verified process tree. Descendants may outlive it. Add tested
   process-tree termination and cleanup ordering, including detached tool
   processes; merely signalling a process group is not enough for every tool.
3. **Serialize writes across dispatch invocations.** There is no repository-wide
   lease around setup/merge/GC. Per-call sequential merges do not protect two
   simultaneous Pi sessions. Merge-resolution edits outside conflicted paths
   also need containment, not a destructive blanket restore of the parent tree.
4. **Verify review target identity before fixes.** GitHub PR diffs may describe
   a different head from the local checkout. The tool does not pin/verify the
   checkout against the PR's head SHA before supplying local context or writing.
5. **Bound agent effort, not just fan-out.** The four-worker limit applies per
   dispatch, not across concurrent calls; there is no run deadline, turn/tool
   budget, or global spend limit. In-process compaction is disabled, and child
   transcript buffers/persisted sessions need retention limits.
6. **Finish evaluation and telemetry coverage.** Add CI, provider fault/abort
   tests, disposable worktree end-state tests, and representative task evals.
   Workflow truncation flags still need complete coverage. Read-only shell
   behavior remains instructional, not enforced.

## Modern spawning: what is worth keeping

Separate contexts, explicit scoped tasks, bounded parallelism, restricted tools,
model failover, and concise result aggregation are sound foundations. They do
not justify a claim of state-of-the-art quality without task evaluations and
cost/latency measurements. Prioritize lifecycle ownership, safety checks, and
local run/worker/attempt tracing over adding more agent roles or deeper nesting.

- [Anthropic: multi-agent research engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
  emphasizes scoped delegation, effort scaling, evaluations and production tracing.
- [OpenAI Agents SDK: tracing](https://openai.github.io/openai-agents-js/guides/tracing/)
  distinguishes run/task/agent spans; a similar local identity hierarchy would
  improve debugging without exporting repository content.
- [Herdr 0.8.2 concepts](https://raw.githubusercontent.com/herdrdev/herdr/v0.8.2/docs/next/website/src/content/docs/concepts.mdx)
  defines workspace/tab/pane grouping. Custom workspace metadata adds indented
  status rows, not clickable child-agent nodes or interactive worker terminals.
